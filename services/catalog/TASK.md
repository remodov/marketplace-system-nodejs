# Шаг 12. Токены, роли и файлы

## Что нужно сделать

У карточки появляются фотографии. Первое желание - принять файл ручкой сервиса и
положить в хранилище самому. Так делать не надо: сервис на каждую картинку держит
соединение и буфер, а на десяти мегабайтах и сотне продавцов цикл событий Node
занят перекладыванием байтов вместо своей работы.

Правильный путь: сервис выдаёт **временную подписанную ссылку**, браузер кладёт
файл прямо в хранилище, мимо сервиса. Сервис решает только одно - кому эту
ссылку выдать.

```
POST /api/v1/products/{productId}/image-upload-url   {"contentType": "image/jpeg"}
-> { "key": "products/<id>/<uuid>", "url": "http://...?X-Amz-Signature=...", "expiresAt": "..." }
```

Две части:

1. **Подпись ссылки.** `S3ImageStorage.presignUpload` подписывает ссылку на `PUT`
   объекта на срок из настроек. `S3Client` уже собран на хранилище стенда: адрес,
   регион и ключи из настроек, `forcePathStyle`. Подпись считает `getSignedUrl` из
   `@aws-sdk/s3-request-presigner`, локально, в сеть при этом никто не ходит. Тип
   содержимого должен войти в подпись: ссылка на `image/jpeg` не примет архив.
   Ключ объекта сценарий уже собирает.
2. **Кто имеет право.** Карточку смотреть может кто угодно, а грузить в неё
   файлы - только владелец. Чужой товар для не-владельца выглядит как
   несуществующий: 404, а не 403. Ключ объекта собирает сценарий: он должен
   говорить, чей это файл.

## Как проверить себя

```bash
docker compose -f ../../infra/compose.yaml up -d postgres-catalog-starter minio minio-init
npm test
```

Только этот файл, без прогона типов: `NODE_OPTIONS=--experimental-vm-modules npx jest test/image-upload.spec.ts`.

Красные «владелец получает подписанную ссылку со сроком» и «чужой товар выглядит
несуществующим»: владелец получает ссылку с подписью `X-Amz-Signature`, сроком
`X-Amz-Expires` и ключом внутри своего товара, чужой товар даёт 404 с кодом
`OWN_PRODUCT_REQUIRED`. Остальные три проверки («неизвестный товар даёт 404»,
«без токена ссылки нет», «не картинка отклоняется на входе») уже зелёные: это даётся.

Для тестов MinIO не нужен: подпись считается локально. Хранилище понадобится,
когда захочешь проверить загрузку руками: консоль MinIO на 9003, логин и пароль
`marketplace`; загрузка - `curl -X PUT "$URL" -H 'Content-Type: image/jpeg' --data-binary @photo.jpg`.

## Грабли presigner

- `getSignedUrl` по умолчанию **не подписывает** `Content-Type`: presigner для S3
  нарочно относит этот заголовок к неподписываемым, чтобы ссылка работала из любого
  клиента. Чтобы тип вошёл в подпись, его надо назвать явно:
  `signableHeaders: new Set(['content-type'])`. Проверь по ссылке: в
  `X-Amz-SignedHeaders` должно стоять `content-type;host`. Без этого по ссылке на
  `image/jpeg` уедет что угодно.
- Без `forcePathStyle: true` клиент собирает адрес с корзиной в имени хоста
  (`marketplace-images.localhost`), а MinIO стенда ждёт `/marketplace-images/<key>`.
  Клиент уже настроен, но помни об этом, когда будешь смотреть на ссылку.
- Свежий SDK по умолчанию считает контрольную сумму тела и для подписанной ссылки
  дописывает в запрос `x-amz-checksum-crc32` пустого тела; у хранилища есть право
  сверить сумму с настоящим файлом и отказать. На клиенте стоит
  `requestChecksumCalculation: 'WHEN_REQUIRED'`, и лишних параметров в ссылке нет.
- Часы. `X-Amz-Date` в ссылке - момент подписи, `X-Amz-Expires` - срок в секундах.
  Момент подписи передавай presigner'у (`signingDate`) из часов сервиса (`Clock`) и
  от них же считай `expiresAt` в ответе, иначе срок в ответе и срок в подписи
  разойдутся. В тестах часы заморожены, и тест ждёт `expiresAt` ровно через
  `IMAGE_UPLOAD_URL_TTL_SECONDS` после них.

## На что посмотреть по дороге

- Проверка токена здесь идёт **без похода в соседний сервис**: в режиме
  `AUTH_MODE=jwt` подпись проверяется локально по ключам Keycloak: `jose` один раз
  скачивает JWKS (`createRemoteJWKSet`) и дальше сверяет подпись сам. Иначе каждый
  запрос к каталогу превращался бы в два, и падение соседа гасило бы всю систему.
- Роль в токене (`seller`, `admin`) отвечает на вопрос «что этому пользователю
  вообще можно», а владение товаром - «можно ли ему вот этот объект». Это разные
  проверки, и вторую нельзя заменить первой: роль смотрит guard, владение - сценарий.
- Почему 404, а не 403 на чужой товар: по разнице кодов можно перебором узнать,
  какие идентификаторы существуют.
- Срок жизни ссылки: десять минут - это компромисс. Что случится, если поставить
  сутки? А если минуту?
- Проверь, что в ссылке действительно есть подпись и срок - тест смотрит именно
  на это, а не на то, что ссылка «какая-то есть».
