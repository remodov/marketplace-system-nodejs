# Шаг 4. Правило живёт внутри модели

## Что нужно сделать

У маркетплейса появилась акция: продавец может уценить товар, но не глубже чем
вдвое. Добавь скидку:

```
PATCH /products/{id}/discount    {"percent": 20}
```

Правила:

- процент от 1 до `MAX_DISCOUNT_PERCENT` (это 50), иначе отказ 400 с пределом в `detail`;
- цена пересчитывается в рублях и копейках - два знака, округление задай явно;
- неудачная попытка не меняет цену вообще.

Главное в этом шаге не скидка, а **где** живёт правило. Проверку «не глубже
половины» нельзя написать ни в контроллере, ни в сервисе - только в методе
`Product.applyDiscount`. Тест домена создаёт товар напрямую, без HTTP и без базы:
если правило окажется в сервисе, тест до него не дотянется и останется красным.

## Где править

`// TODO шаг 4` в `product.entity.ts`, `product.dto.ts`, `product.controller.ts`.
Заготовка в сущности на месте и ничего не делает: скидка «применяется» без
изменений; сервис уже зовёт её, а ручки нет.

## Как проверить себя

```bash
npm test
```

Красные `test/rules.spec.ts` (восемь проверок, без базы) и
`test/discount-api.spec.ts` (две проверки, через HTTP). Обрати внимание на два
теста из первого файла:

- «состояние меняется только через методы» - у `Product` все поля `private`, и
  строки с `@ts-expect-error` живут только потому, что прямая запись `p.price = x`
  не компилируется. Открой поле - `tsc` в `npm test` упадёт на «Unused
  '@ts-expect-error' directive». Правило, которое можно обойти, присвоив поле,
  это не правило, а пожелание.
- «скидка округляется до копеек» - 33% от 999.99 даёт 669.9933; тест ждёт 669.99.
  Просто `mul` этого не сделает, нужен `toDecimalPlaces(2)`.

Посмотри на время выполнения: доменные тесты идут за миллисекунды, потому что не
ходят в базу. Это не мелочь - такие тесты можно гонять после каждой правки:
`NODE_OPTIONS=--experimental-vm-modules npx jest test/rules.spec.ts`.

## На что посмотреть по дороге

- Почему процент проверяется в модели, а «поле `percent` не пришло» - в DTO.
  Граница простая: формат запроса - снаружи, смысл - внутри.
- `Decimal` из `decimal.js` и деньги: почему не `number` и зачем явное
  `toDecimalPlaces(2)`. У `Decimal` округление по умолчанию `ROUND_HALF_UP` -
  проверь это в документации, а не на слово.
- `private` в TypeScript живёт только в компиляторе: в JavaScript поле на месте,
  и `(p as any).price = 1` пройдёт. Защита здесь - дисциплина типов и то, что
  `npm test` начинается с `tsc`. Поля `#price` надёжнее, но декораторы TypeORM
  на них не навесить - это цена выбора ORM.
- Что случилось бы, будь поля открыты: сервис смог бы поставить любую цену, и
  правило перестало бы существовать, хотя код никуда не делся.
