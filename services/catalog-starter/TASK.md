# Шаг 2. Фильтр каталога по цене

## Что нужно сделать

Ручка `GET /products` умеет отдавать весь каталог и искать по названию.
Добавь необязательный параметр `maxPrice`:

```
GET /products?maxPrice=2000
```

С ним ручка отдаёт только товары не дороже указанной цены, отсортированные
по возрастанию цены. Без параметра поведение прежнее - весь каталог.

## Где править

Четыре файла в `src/product`, в каждом стоит `// TODO шаг 2`:

| файл | что там сделать |
|---|---|
| `product.store.ts` | метод выборки в интерфейсе `ProductStore` |
| `product.repository.ts` | запрос через query builder с условием и сортировкой |
| `product.service.ts` | сценарий чтения `cheaperThan` |
| `product.controller.ts` и `product.dto.ts` | необязательный параметр и выбор сценария |

Параметр приходит строкой; в число его превращает контроллер, и мусор вроде
`maxPrice=дорого` должен получить 400 с именем поля, а не пятисотку.

## Как проверить себя

```bash
npm test
```

Файл `test/filter.spec.ts` красный: фильтр отсекает лишнее, дешёвое идёт первым,
граница включается (товар ровно за `maxPrice` попадает в выдачу), запрос без
параметра по-прежнему отдаёт весь каталог, а мусор в параметре даёт 400 с полем
`errors.maxPrice`. Задание сделано, когда он зелёный и не сломались пять тестов
из `api.spec.ts`.

## На что посмотреть по дороге

- Деньги в `Decimal` из `decimal.js`, а не в `number`: `2000` и `1999.99` должны
  сравниваться точно. В запрос параметр уходит строкой с двумя знаками.
- Граница `<=` против `<` - в требовании написано «не дороже», это включающее
  условие. Тест на границу существует именно потому, что здесь легко ошибиться.
- Сортировать надо по колонке таблицы: `orderBy('p.price')`. Колонка `numeric`
  приходит из `pg` строкой, и если отсортировать уже на стороне JavaScript
  как строки, `2000.00` окажется раньше `450.00`.
- Что уходит в базу: запусти тесты с `SQL_LOG=1` или выполни в `psql`
  `explain select * from products where price <= 2000 order by price` - по цене
  индекса нет и сортировка идёт в памяти.
