# Шаг 3. Команды, валидация и коды ошибок

## Что нужно сделать

Каталог умеет только читать и создавать. Добавь две команды:

```
PATCH /products/{id}/price    {"price": 1490.00}
PATCH /products/{id}/stock    {"delta": 7}     поступление
PATCH /products/{id}/stock    {"delta": -3}    списание
```

Обе отвечают обновлённым товаром. Правила отказов:

| ситуация | код | откуда берётся отказ |
|---|---|---|
| цена не число, отрицательная или не пришла | 400 | декораторы `class-validator` в DTO, в теле поле `errors.price` |
| `delta` не пришла | 400 | то же, поле `errors.delta` |
| `delta` нулевая | 400 | смысл команды, вход формально корректен: ошибка из класса `Product` |
| списание уводит остаток в минус | 409 | состояние товара: сейчас так нельзя |
| товара с таким id нет | 404 | уже реализовано, ломать не нужно |

Разница между 400 и 409 - здесь главное. 400 - «запрос неправильный, его нельзя
даже начать выполнять». 409 - «запрос правильный, но текущее состояние не даёт его
выполнить»: завтра товар довезут, и тот же самый запрос пройдёт.

## Где править

`// TODO шаг 3` стоит в четырёх файлах `src/product`: `product.entity.ts`,
`product.service.ts`, `product.dto.ts`, `product.controller.ts`.

Фильтр `ProblemFilter` в `src/http/problem.ts` трогать не нужно - он уже переводит
ошибки в ответы и служит образцом. Посмотри на него первым: `instanceof` по классам
ошибок показывает, какая ошибка каким кодом обернётся, и это подсказывает, что
бросать из класса `Product`. Пропавшее поле в JSON ловит `@IsDefined()`: без него
`@IsInt()` на `undefined` молчит.

## Как проверить себя

```bash
npm test
```

Красный `test/change-api.spec.ts` - семь проверок, по одной на строку таблицы плюс
успешные сценарии. Тело ответа на 400 обязано называть поле: тест смотрит в
`errors.price` и `errors.delta`. Остальные тесты должны остаться зелёными.

## На что посмотреть по дороге

- Неудачное списание не должно менять остаток - тест это проверяет отдельно.
  Если остаток «уполз», значит состояние поменяли до проверки.
- PATCH против PUT: PUT заменяет ресурс целиком, а мы меняем одно поле.
- 422 вместо 400 - тоже встречается; посмотри в материале, почему на практике
  чаще останавливаются на 400.
- Ошибка с данными (`OutOfStockError` с `requested` и `available`) против ошибки
  без них (`InvalidError`): первую фильтр разбирает, когда нужны подробности в
  `detail`, вторую - когда важен только вид.
- Деньги приходят в JSON числом, а в класс уходят `Decimal`: превращение
  `new Decimal(String(body.price))` живёт в контроллере, сервис про JSON не знает.
